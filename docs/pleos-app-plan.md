# 차박이네 Pleos 앱 기획서

Pleos(현대차그룹 인포테인먼트, Android Automotive OS 기반)용 차박이네. iOS 앱 → Android 앱 다음 순서로 만든다(로드맵은 §9). 지금은 **개발이 아니라 기획과 조건 확인 단계**다.

확인한 사실은 Pleos 문서(`document.pleos.ai`) 출처이고, 확인하지 못한 것은 `TBD`로 두었다. 입점 조건·수수료·카테고리는 Pleos Playground 로그인과 partnership@pleos.ai 문의로만 알 수 있다.

## 1. 한 줄 정의

차 안 큰 화면에서 **주행 중에는 "어디서 차박하지?"를 찾아 내비 길안내까지 이어 주고, 주차하면 "차박 모드"로 바뀌는 앱.** 두 모드로 나뉜다.

| 모드 | 언제 | 하는 일 |
|---|---|---|
| **찾기 모드** | 주행 중 (기본) | 장소 찾기 · 리뷰/신호등 확인 · 목적지 설정 → **Pleos 내비에서 길안내 시작** |
| **차박 모드** | 주차했을 때 | 도착 확인 · 차박 준비(조명·공조·좌석) · 배터리 안내 · 주변 시설 · 밤 화면 |

## 2. 왜 차 안에서 필요한가

- 차박은 차에서 장소를 정한다. 휴대폰 앱은 이미 있지만(iOS/Android) 운전 중에는 폰을 못 만진다. 차 화면에서 "근처 어디가 되나"를 보고 바로 내비로 보내는 흐름이 가장 자연스럽다.
- 도착해서 주차한 순간에도 같은 앱이 이어져야 한다. 장소의 신호·규칙을 다시 확인하고 차박 준비를 하는 곳이 폰이 아니라 차 화면이다.
- 핵심 가치는 iOS와 같다. **합법·안전 신호등(허용 / 조건부 / 금지·위험) + 이유·출처·최종 확인일·신뢰도**. 차량용에서는 더 크고 짧게 보여 준다.

## 3. 범위와 사용 흐름

```
[주행 중: 찾기 모드]
 홈(주변 지도+목록) → 장소 카드(신호·거리·별점) → 리뷰 요약
   → "여기로 안내" → Pleos 내비 길안내 시작 (NaviHelper SDK)
        ↓ 도착, 주차 (P단 + 주차 브레이크)
[주차: 차박 모드]
 "차박 모드를 켤까요?" (자동 시작 아님, 물어본다) → 차박 모드
```

주차한다고 바로 차박 모드를 켜지 않는다. 마트나 휴게소에 서도 주차가 되므로 **"차박 모드를 켤까요?"로 한 번 묻는다**. 목적지로 안내해 온 장소에 도착한 경우는 그 장소로 바로 이어서 보여 준다.

### 3.1 찾기 모드 (v1, 주행 중)
| 기능 | 내용 |
|---|---|
| 내 주변 장소 | 현재 위치 기준 가까운 순 목록 + 지도 (신호등 색 마커) |
| 장소 카드/상세 | 신호등, 이름, 거리, 별점, **한 줄 이유**. 긴 본문은 주차 중에만 펼침 |
| 리뷰 보기 | 별점 요약 + 최근 리뷰 1~2개를 짧게. 주행 중에는 글을 읽게 하지 말고 **음성으로 읽어 주기**(TextToSpeech) 우선. 리뷰 작성은 폰에서 (키보드/사진) |
| 필터 | 신호(초록/노랑/빨강), 지역, 편의시설 프리셋 칩 |
| 음성 검색 | "속초 차박 가능한 곳" (SpeechToText SDK) |
| **길안내 시작** | 목적지 설정·확정을 NaviHelper SDK로 Pleos 내비에 넘기고, 길안내는 내비가 한다. 우리 앱은 길안내를 직접 하지 않는다 |
| 즐겨찾기 | 기기 저장 + 로그인 시 서버 동기화 (읽기 중심) |
| 축제·이벤트 | 근처 축제 표시 |

### 3.2 차박 모드 (주차 중)
Vehicle 퍼미션이 **없어도 되는 기본 기능**과, **승인되면 켜는 차량 연동 기능**으로 나눈다. 승인이 안 되면 기본만 낸다.

| 구분 | 기능 | 필요한 것 |
|---|---|---|
| 기본 | 장소 상세 전체: 이유·출처·확인일·신뢰도, 편의시설(화장실·수도·전기), 계절 규칙, 임시검증 안내 띠 | 없음 |
| 기본 | **차박 체크리스트**: 시동 끄기, 유틸리티 모드 켜기, 환기, 쓰레기 되가져가기 등 순서 안내 카드 (시동·유틸리티 모드는 앱이 못 하므로 운전자가 직접) | 없음 |
| 기본 | 밤 화면: 어두운 지도·큰 글씨(표준 `NIGHT_MODE` 읽기), 알람/방해 최소화 | 없음 |
| 기본 | 주변 시설·내일 아침 일정(축제 포함), 철수 안내 | 없음 |
| 연동 | EV 배터리 잔량/전비로 **"오늘 밤 머물 수 있는 시간"** 안내 | `CAR_ENERGY` 승인 (§6.2) |
| 연동 | 앰비언트 조명 색 변경 | 조명 제어 승인 (§6) |
| 연동 | 공조 설정 (캠핑용 약풍) | 공조 제어 승인 |
| 연동 | 앞좌석 눕히기(평탄화) 프리셋 | 시트 제어 승인, 차종별 지원, P단·주차 브레이크 중에만, 끼임 방지는 Pleos 정책 |
| 연동 | 환기: 창문 조금 열기 (1시간마다, 비 오면 닫기) | Vehicle SDK Window 도메인 제어 승인, 차종별 지원. 시동 끈 뒤 동작 여부 미확인. 승인 안 되면 환기 알림만 |
| 불가 | **시동 끄기, 유틸리티 모드 전환** | 바꾸는 API가 없다: 표준 속성은 읽기 전용이고 Vehicle SDK에도 해당 도메인이 없다 (§6.1) |

### 3.3 하지 않음
- **제보·리뷰 작성**(글·사진): 키보드와 사진이 필요해 차량에 맞지 않는다. 폰 앱에서 한다. 내 제보 결과 **보기**만 v2 후보.
- 로그인 화면에서 비밀번호 입력, 사진 업로드, 계정 삭제 — 폰에서 처리.
- 영상·게임·브라우저형 화면 — 주행 중 잠기는 범주.
- 충전 제어, 도어 등 차박과 무관한 차량 제어. (창문은 환기용으로만 §3.2 연동에 둔다)

### 3.4 v2 후보
- 도착 후 주변 시설 음성 안내, 철수 후 리뷰 작성 요청 푸시(폰으로).
- 내 제보 처리 결과 보기.

## 4. 화면 구성

폰의 TabView 구조 대신, 차량 화면(가로 대화면)에 맞춰 **좌측 목록 / 우측 지도** 2분할을 기본으로 한다. 호환 모드·레터박스는 금지라 해상도별 레이아웃을 직접 대응해야 한다. 상단에 현재 모드(찾기/차박)를 표시하고, 주차 중에는 모드를 수동으로 바꿀 수 있다.

| 화면 | 주행 중 (찾기 모드) | 주차 중 (찾기·차박 모드) |
|---|---|---|
| 홈(지도+주변 목록) | 지도 보기·목록 스크롤, 검색은 음성/프리셋만 | 전체 |
| 장소 상세 | 신호·이름·거리·별점·**길안내 시작**만 요약, 긴 본문은 접음 | 전체 (이유·출처·시설·리뷰) |
| 리뷰 | 별점 요약 + 음성 읽기 | 전체 목록 |
| 즐겨찾기 | 목록 + 길안내만 | 전체 |
| 필터 | 프리셋 칩만 | 열기 가능 |
| **차박 모드 화면** | 없음 | 체크리스트, 배터리/조명/공조/좌석 카드, 주변 시설 |
| 설정/약관/계정 | 잠금 | 읽기 |

디자인 원칙: 버튼 **12.5×12.5mm 이상**, 글자 크게, 한 화면 정보량 줄이기, 입력은 음성·프리셋 우선, 신호등은 색뿐 아니라 글자·아이콘 병행(색각 이상 대응).

## 5. 사용하는 Pleos Connect SDK

| SDK | 쓰는 곳 | 상태/메모 |
|---|---|---|
| NaviHelper | 목적지 설정·확정·취소, 경유지, 경로 탐색 결과 수신 | 퍼미션 목록은 문서 본문에 없음 → API Reference 확인 |
| Fused Location | 내 주변 장소 계산용 차량 위치 | 개요 페이지는 "준비 중", 호환성 표는 Pleos 차량 **미지원**. 표준 Android 위치 API 사용 가능 여부 확인 필요 (§12). 안 되면 지도에서 직접 고르는 방식으로 대체 |
| SpeechToText | 음성 검색 | 마이크 접근 설정 필요 |
| TextToSpeech | 주행 중 리뷰 음성 읽기, 도착 안내 | — |
| Vehicle SDK | 차박 모드의 배터리·조명·공조·좌석 (승인되는 만큼) | 아래 §6 |
| ADAS | 사용 안 함 | — |

공통 규칙: 각 SDK는 `initialize()` → 사용 → `release()` 순서, 결과는 `onComplete`/`onFailed` 비동기 콜백으로 온다(콜백이 끝나기 전에 `release()` 금지). Vehicle 도메인은 먼저 `checkXXXCapabilities`로 지원 여부를 확인한다.

## 6. 차량 데이터(Vehicle SDK)와 퍼미션

Vehicle SDK 퍼미션은 매니페스트에 `pleos.car.permission.{상수명}`으로 선언한다(`CAR_*` 조회, `CONTROL_CAR_*` 제어). 2026-11-14에 확인한 문서("Declaring permission")에는 App Market 승인·협의 절차가 적혀 있지 않고, 운영사무국도 공모전 개발에 승인이 필요 없다고 답했다(11-11). 실제 차량에서 어떤 퍼미션이 허용될지는 아직 모르므로, **v1의 찾기 모드와 차박 모드 기본 기능은 Vehicle 퍼미션 없이 동작**하게 만들고, 차박 모드의 차량 연동(§3.2)은 허용되는 만큼 켠다. 퍼미션이 거부돼도 앱은 정상 동작해야 한다.

문서에서 확인한 도메인별 조회 퍼미션(`pleos.car.permission.…`):

| 도메인 | 퍼미션 | 차박이네 용도 |
|---|---|---|
| DrivingMode, Brake, Odometer | `CAR_DRIVE` | 주차 브레이크 상태로 "정차 중" 판단 후보 (§7) |
| EvBattery, Fuel | `CAR_ENERGY` | 차박 모드: 잔량 기반 "머물러도 되는지" 안내 |
| HVAC | `CAR_CLIMATE` | 차박 모드: 공조 설정 |
| CarInfo | `CAR_INFO` | 차종 정보 (필요성 낮음) |
| Window, Wiper | `CAR_WINDOWS` | 차박 모드: 환기용 창문 상태 조회 (제어는 `CONTROL_CAR_*` 승인 시) |

참고:
- `CAR_*`는 조회, `CONTROL_CAR_*`는 제어. 차박 모드의 조명·공조·좌석·창문 제어만 `CONTROL_CAR_*`가 필요하다.
- 퍼미션 누락 시 `onFailed`로 `ERROR_SECURITY_PERMISSION`이 올 수 있다. 거부돼도 앱이 동작해야 한다(기능 축소).

### 6.1 표준 차량 정보(AAOS Car API)와 제어 한계 (문서 확인, 2026-03 기준 표)
Pleos 문서는 속도·기어 같은 **표준 차량 데이터는 Android Automotive 표준 API를 쓰라**고 한다. Pleos Connect SDK는 표준에 없는 제조사 전용 기능(시트 제어, 특수 조명, 보안 인증)에만 있다. 표준 속성의 개별 번호(VHAL Property ID)를 직접 쓰거나 차종별로 분기하면 안 된다.

| 속성 | 앱에서 읽기 | 차박이네 용도 |
|---|---|---|
| `PERF_VEHICLE_SPEED` | 가능 | 주행/정차 판단 (§7) |
| `GEAR_SELECTION` | 가능 (`CURRENT_GEAR`는 불가) | 주차(P) 판단 |
| `PARKING_BRAKE_ON` | 가능 | 정차 판단 보조 |
| `IGNITION_STATE` | 가능 | 시동 상태 표시 (끄기는 불가) |
| `EV_BATTERY_LEVEL`, `EV_CHARGE_STATE`, `EV_CHARGE_PORT_CONNECTED`, `RANGE_REMAINING` | 가능 | 차박 모드 배터리 안내 |
| `NIGHT_MODE` | 가능 | 지도 밝기 자동 전환 |
| `FUEL_LEVEL_LOW` | 가능 (`FUEL_LEVEL`은 불가) | 내연기관 경고만 |
| `ENV_OUTSIDE_TEMPERATURE` | 가능 | 야간 외기온 안내 |
| HVAC 세부, 와이퍼, 타이어, 좌석 점유 | 불가 | — |
| 위치 | 원시 위치 속성 없음 | Fused Location은 Pleos 차량에서 "미지원"으로 표기 → §12 |

**표준 속성으로는 제어가 안 된다**: 문서에 "제3자 앱은 속성을 읽기만 하고, 사용 가능한 속성이라도 **쓸 수 없다**"고 되어 있고, 전원 상태 요청(`AP_POWER_STATE_REQ`)은 폐기(사용 불가)다. 서명·특권 퍼미션이 필요한 속성은 제3자에게 열리지 않는다. 따라서 **앱에서 시동 끄기는 불가**이고, **유틸리티 모드 전환은 표준 속성 표와 Vehicle SDK 도메인 목록 어디에도 없다**(DrivingMode 도메인은 드라이브 모드·크루즈 정보 조회). 앰비언트 조명·공조는 Vehicle SDK의 제어(`CONTROL_CAR_*`)로 가능성이 있지만 차종별 지원(`checkXXXCapability`)과 승인이 전제다.

**정정 (2026-10-25 확인, Vehicle SDK v2.3.2 문서)**: 위의 "읽기 전용"은 AAOS 표준 속성에 대한 제한이다. Pleos 전용 Vehicle SDK는 별도로 Door, Window, HVAC, Light, Seat, Wiper, Steeringwheel 등 도메인의 제어(set) API를 제공한다. 따라서 **창문은 Window 도메인으로 제어할 수 있고**(승인·차종 지원 전제), 시동·전원과 유틸리티 모드는 도메인 목록(19개)에 없어 여전히 불가로 본다.

### 6.2 전기차(EvBattery) API 목록 (Vehicle SDK, 퍼미션 `CAR_ENERGY`)
`ai.pleos.playground.vehicle.api.EvBattery` 인터페이스의 함수 이름 목록이다. 시그니처·퍼미션·콜백 타입은 목록 페이지에 없고 함수별 상세 페이지에 있다(미확인). 모든 호출은 `onComplete`/`onFailed` 비동기이고, 쓰기 전에 `check…Capabilities`로 지원 여부를 확인한다.

| 구분 | 함수 | 의미 |
|---|---|---|
| 조회 | `getEvBatteryStateOfCharge` | 배터리 잔량(SOC) |
| 조회 | `getEvChargeSwitchState` | 충전 스위치 상태 |
| 조회 | `getEvChargeCurrentDrawLimit` | 충전 전류 제한 |
| 조회 | `getCurrentEvEfficiency` | 현재 전비 |
| 조회 | `getInstantaneousEvEfficiency` | 순간 전비 |
| 조회 | `getSinceChargeEvEfficiency` | 충전 이후 전비 |
| 조회 | `getCumulativeEvEfficiency` | 누적 전비 |
| 구독 | `registerEvBatteryStateOfCharge` / `unregister…` | 잔량 변화 |
| 구독 | `registerCurrentEvEfficiency`, `…InstantaneousEvEfficiency`, `…SinceChargeEvEfficiency`, `…CumulativeEvEfficiency` (각 `unregister…` 포함) | 전비 변화 |
| 제어 | `setEvChargeSwitch` | 충전 시작/중지 |
| 제어 | `setEvChargePortOpen` | 충전구 열기 |
| 제어 | `setEvChargePercentLimit` | 충전 상한(%) |
| 제어 | `setEvChargeCurrentDrawLimit` | 충전 전류 제한 |
| 지원 확인 | `checkEvBatteryStateOfChargeCapabilities`, `checkEvChargeSwitchCapabilities`, `checkEvChargePortOpenCapabilities`, `checkEvChargePercentLimitCapabilities`, `checkEvChargeCurrentDrawLimitCapabilities`, `checkCurrentEvEfficiencyCapabilities`, `checkInstantaneousEvEfficiencyCapabilities`, `checkSinceChargeEvEfficiencyCapabilities`, `checkCumulativeEvEfficiencyCapabilities` | 기능별 지원 여부 |

이 목록에 **주행 가능 거리와 V2L(외부 전력 공급) 함수는 없다.** 주행 가능 거리는 표준 속성 `RANGE_REMAINING`(읽기 가능, §6.1)으로 얻는다. V2L 상태·제어 방법은 확인하지 못했다 → 차박에 중요하므로 문의 항목에 넣는다.

차박이네 쓰임: 차박 모드에서 `getEvBatteryStateOfCharge`/`register…`(잔량)와 전비 함수로 "오늘 밤 머물 수 있는 시간"을 추정한다. 충전 제어(`set…`)는 쓸 이유가 적고 제3자에게 열릴지 불확실해 **쓰지 않는다**. 충전 상태·충전구 연결은 표준 속성(`EV_CHARGE_STATE`, `EV_CHARGE_PORT_CONNECTED`)으로도 읽힌다.

### 6.3 Vehicle Data API (클라우드, 차 밖에서 차량 데이터 조회)
차 안 SDK와 별개로 Pleos에는 **클라우드 REST API**(`https://api.pleos.ai/v1/vehicles/{vin}/…`)가 있다. 현대·기아·제네시스 커넥티드카의 텔레매틱스 데이터를 OAuth 2.0 토큰으로 조회한다.

| 엔드포인트 | 내용 |
|---|---|
| `/batteries` | 충전 상태, 플러그 연결, 배터리 잔량, 완충까지 시간 |
| `/powertrains`, `/powertrains/data` | 엔진·모터·배터리 시스템 상태, 원천 데이터 |
| `/locations` | 좌표, 고도, 방향, 속도 |
| `/driving`, `/driving/data` | 시동 상태, 주행 거리, 주차 상태 |
| `/status`, `/status/data` | 도어·트렁크·타이어 압력·경고·공조 |
| `/speed`, `/freezer` | 속도 원천 데이터, 냉동고 상태 |

제약: **2026-08 기준 유럽에서만 제공**이고 다른 지역은 "준비 중"이라 한국 제공 여부는 확인되지 않았다. 개인 이용자는 API 키를 받으면 바로 쓰지만(유럽), 값이 오래됐거나 없을 수 있고 폴링으로 차를 깨울 수 없다. 모델별로 항목이 다르다. → **차박이네 기획에 쓰지 않는다**(한국 미제공, 앱이 차 밖에서 차량 데이터를 볼 필요도 없음). 한국 제공 계획만 문의 목록에 둔다.

## 7. 주행 상태 대응 (심사 핵심)

**먼저 알아야 할 것**: Pleos 문서의 주행 제한 정책에 따르면, **주행 방해 최적화(DO, Distraction Optimization)를 갖추지 않은 앱은 공회전·주행 중 종료되고 주차 중에만 쓸 수 있다.** 차박이네의 찾기 모드는 **주행 중 사용이 핵심**이므로 DO 대응(인증 조건은 `TBD`, §12)이 사실상 필수다. 대응하지 못하면 "주차 중 전용 앱"이 되어 찾기 모드의 가치가 크게 줄어든다. **가장 큰 심사 위험**은 주행 중 장소·리뷰 탐색이 "운전 방해"로 보이는 것이므로, 주행 중 화면은 요약 카드·음성·내비 넘기기 중심으로 설계해 위험을 낮춘다. 지역별 표(한국은 별도 행이 없고 "기타 지역"에 해당할 가능성이 높으나 미확정)는 다음과 같다. 주차 중에는 모두 허용.

| 기능 (공회전·주행 중) | 북미 | 유럽 | 기타 지역 |
|---|---|---|---|
| 키보드, 다이얼패드, 내비 검색 | 금지 | 허용 | 허용 |
| 검색 | 음성만 | 허용 | 허용 |
| 미디어 앱 로그인·설정 | 금지 | 금지 | 허용 |
| 디지털키·도어·**시트**·차량 설정 | 금지 | 금지 | 금지 |
| 영상 시청, **QR 로그인**, 큰 글씨 매뉴얼 | 금지 | 금지 | 금지 |

이 표로 알 수 있는 것: 시트 제어는 어느 지역이든 **주행 중 금지**(주차 중만), QR 로그인도 주차 중에만 가능하다. 아래 설계는 이 표보다 보수적으로(검색은 음성·프리셋 우선) 한다.

문서 기준 주행 중에는 영상·게임·브라우저·상세 설정이 잠기고, **앱이 주행 상태를 감지해 기능을 줄여야 한다**. 지도 조작과 목록 스크롤은 별도 규정이 없고 검색·키보드는 프리셋/음성을 우선하라고만 되어 있다. 가이드를 지켜도 운전 방해 위험이 보이면 반려될 수 있다.

설계:
- 앱은 상태를 `정차 / 주행`으로 나누는 **단일 모드 객체**(`DrivingState`)를 두고, 모든 화면이 이를 본다. 판단 소스는 표준 속성 `PERF_VEHICLE_SPEED`, `GEAR_SELECTION`(P), `PARKING_BRAKE_ON`이며(§6.1, 모두 읽기 가능), 이 객체 한 곳만 이를 읽는다.
- **모르면 주행으로 간주**(안전 쪽). 신호를 못 받아도 위험한 입력 UI는 열지 않는다.
- 주행 중 금지: 텍스트 입력, 긴 본문 읽기, 사진 크게 보기, 로그인·약관·설정, 팝업 연타. 허용: 지도 이동/확대, 목록 스크롤, 요약 카드(신호·거리·별점), 리뷰 **음성 읽기**, 음성 검색, **길안내 시작(내비로 넘기기)**. 차박 모드 화면은 주차 중에만 열린다.
- 상세 정보는 신호등·이름·거리로 **한눈에 1.5초 안에** 읽히게 한다.
- 지역별 주행 제한 정책이 따로 있다(Vehicle App Planning Guide의 Driving Restriction Policy by Region). 한국 기준을 확인한다 (`TBD`).

## 8. 데이터와 서버

iOS·Android와 **같은 서버·같은 계약**을 쓴다. 새로 만들 서버 기능은 없다.

- 장소: `GET /static/places/manifest.json` → `places-v{N}.json` (스키마는 iOS `places.json`과 동일, 번호 `KR-{ISO 시도 숫자}-{시군 2자}-{순번}`)
- 축제: `festivals.json` (서버 수집·관리자 검수)
- 제보 집계: `/static/aggregates/places.json`
- 인증이 필요한 호출(즐겨찾기 동기화 등): `Authorization: Bearer <Firebase ID 토큰>` — 계약 chabakine-admin 저장소의 `docs/server-api.md`
- 캐시·폴백: 서버가 죽어도 번들/캐시 데이터로 둘러보기가 되어야 한다 (iOS와 같은 원칙). 차량은 통신이 불안정하므로 **오프라인 우선**이 더 중요하다.
- 원격 데이터는 `sha256`·개수·번호 형식을 검증한 뒤 저장한다 (iOS와 동일).

### 8.1 폰(iOS/Android) ↔ Pleos 데이터 주고받기

**결론: Pleos가 폰 앱과 데이터를 직접 주고받는 공식 수단은 문서에서 찾지 못했다.** 확인한 것:
- Pleos 가이드에 폰 연동·동기화 항목이 없고, 폰 기능(전화·문자·캘린더·연락처)은 차 안에서 제한되어 선택 기능으로 두라고만 한다. 외부 서버나 모바일 앱과의 동기화, QR·기기 코드 로그인은 "다루지 않음"이다.
- 통신은 앱이 자기 서버와 하는 일반 네트워크이고, 네트워크 권한·서버 프로토콜 규정은 문서에 없다(차는 자체 통신망이나 Wi-Fi를 쓰며 **폰의 인터넷에 의존하지 않는다**. 앱은 폰 없이도 받는다).
- 따라서 **우리 서버가 공통 통로**다. 구조는 이미 맞다: iOS·Android·Pleos가 같은 서버 API(chabakine-admin 저장소의 `docs/server-api.md`)와 같은 계정(Firebase 로그인 uid)을 쓰면 즐겨찾기가 기기 사이에서 동기화된다. 서버에 새로 만들 것은 없다.

차에서 계정을 연결하는 방법(후보, 우선순위순):
1. **로그인 없이 시작**(v1 기본): 둘러보기와 기기 즐겨찾기만. 로그인이 필요 없어 심사 위험이 가장 낮다.
2. **폰으로 연결(기기 코드)**: 차 화면에 짧은 코드나 QR을 띄우고, 폰 앱(로그인된 상태)에서 승인하면 서버가 그 차 기기에 토큰을 준다. 서버에 "기기 연결" API가 새로 필요하다(`TBD`). 문서상 QR 로그인은 **주차 중에만** 허용이다. 차에서 직접 구글·애플 로그인은 키보드 입력과 정책 때문에 권하지 않는다.
3. 폰 앱의 즐겨찾기를 **내보내기/가져오기**(링크 공유 등)는 서버 계정 연결 없이도 되지만 번거롭다.

계정 관련 규칙(문서 확인): 차주나 운전자가 바뀔 때 **로그아웃·계정 전환이 쉬워야** 하고, 로그인 토큰은 **Keystore** 같은 보안 저장소에 보관한다. 위치·음성·계정 동의는 이유를 간단히 밝힌다. 불필요한 개인정보를 저장하지 않고 로그에서 가린다.

오프라인(문서 확인): 연결이 끊기거나 느려질 수 있다고 전제하고 ① 최근 본 내용 로컬 캐시, ② 재시도·타임아웃 처리, ③ 오프라인 상태를 보여 주는 UI, ④ 저대역폭 모드를 갖춘다. 번들·캐시 우선 원칙(위)과 일치한다.

**데이터 흐름 요약**

| 방향 | 방법 |
|---|---|
| 서버 → iOS/Android/Pleos | 장소·축제·집계 정적 파일 (동일) |
| iOS/Android ↔ 서버 ↔ Pleos | 즐겨찾기 동기화 (같은 계정일 때) |
| 폰 → Pleos 직접 | 공식 수단 없음 (서버 경유) |
| Pleos → 서버 | 제보는 폰에서만, 차는 읽기 중심 |
| Pleos 차량 데이터 → 서버 | 보내지 않음 (위치 포함, §11) |

**지도**: iOS의 MapKit은 못 쓴다. 2026-10-25 확인 결과 **Pleos 공식 SDK에 지도 컴포넌트는 없다**(NaviHelper는 Pleos 내비 앱을 제어할 뿐 지도를 그리지 않는다). Google 지도는 Google Play 서비스(GMS)가 있어야 하는데 Pleos 단말에 있는지 확인하지 못했고, 국내 길안내도 지원하지 않아 후보에서 사실상 제외한다. 단계별 계획:

| 단계 | 내용 | 조건 |
|---|---|---|
| 0 (PT 프로토타입) | 지도 없음. 후보 목록 + 상세 + "내비로 안내"(NaviHelper로 목적지 전달, 내비 화면 요청) | 없음. 심사·용량 위험이 가장 낮다 |
| 1 (지도 허용 확인) | 설명회에서 외부 지도 SDK·GMS 허용 여부를 확인한다 (설명회 질문 13~14) | 답변 대기 |
| 2 (선택) | 허용되면 **MapLibre**로 장소 마커(신호등 색)만 얹은 가벼운 지도. 야간에는 `NIGHT_MODE`에 맞춰 어두운 스타일 | 타일 출처·이용 약관, 오프라인 동작, 용량을 먼저 정한다. 카카오·네이버 SDK는 차량 탑재 약관이 허용할 때만 |
| 3 (미정) | Pleos가 지도 컴포넌트나 GMS를 제공하면 그쪽으로 교체 | 운영사 공지 |

지도를 넣어도 주행 중에는 조작을 줄이고(이동·확대만), 길안내는 항상 Pleos 내비에 넘긴다.

## 9. 개발 순서와 구조

1. iOS v1.0 출시 → 전국 데이터 확장
2. Android 앱 (`app-phone`)
3. Pleos 앱 (`app-auto`)

Android 시작 때 모듈을 나눈다.

```
android/
├─ core/        장소 모델·저장소·서버 클라이언트·신호 규칙·검증 (UI 없음)

└─ app-auto/    Pleos UI, DrivingState, NaviHelper/Location/STT 연동
```

`core`에 로직을 모으면 Pleos 앱은 UI와 차량 SDK 연동만 만들면 된다.

## 10. 개발·심사 조건 (문서 확인)

- 언어 Java/Kotlin, minSDK 28 이상, Gradle 8.0 이상
- 에뮬레이터(Pleos Connect Emulator)는 **요청해야 제공**. SDK는 에뮬레이터 환경에서 개발·검증

## 11. 개인정보·약관

- 폰 앱과 같은 개인정보 수집 범위를 유지한다. 차량 위치는 **기기 안에서 가까운 장소를 고르는 데만** 쓰고 서버로 보내지 않는다 (iOS와 동일 원칙).
- 분석·광고 SDK는 쓰지 않는다.
- Pleos 앱 등록 시 개인정보처리방침 URL이 필요할 가능성이 높다 → 기존 `chabakine-legal` 문서를 쓰되 차량 위치 항목을 추가해야 하는지 검토 (`TBD`).
- 데이터 임시검증 상태 안내 띠는 차량 화면에도 그대로 둔다. "검증된" 같은 표현은 쓰지 않는다.

| 한국 주행 제한 정책 적용 지역(기타 지역?)과 DO(주행 방해 최적화) 인증 방법·조건 | Driving Restriction Policy by Region / Development Guide, 문의 |
| Vehicle Data API(클라우드)의 한국 제공 계획 | Pleos 문의 (기획에는 쓰지 않음) |

### 일부만 풀린 것

| 항목 | 지금 상태 | 남은 것 |
|---|---|---|
| 앰비언트 조명·공조·시트·창문 제어(`CONTROL_CAR_*`) | 매니페스트 선언으로 쓰며, 문서("Declaring permission", 11-14 확인)에 승인 절차가 없다. 받지 못한 항목은 "지원하지 않음"으로 둔다. | 실제 차량에서 허용되는지, 차종별 지원, 시트 정차 조건·끼임 방지 정책 |
| 폰 앱과 연결하는 방법 | 기기 코드·QR(폰에서 승인) 화면을 시연용으로 구현했다. | Pleos 공식 방법·로그인 정책이 있는지, 서버 차량 연결 API |
| 지도 표시 수단, 로그인 방식 | 지도는 카카오맵을 쓴다. 차량 앱은 로그인 없이 읽기 중심이다. | Pleos가 허용하는 지도·로그인 방식인지 |

### 풀린 것

| 항목 | 답 |
|---|---|
| 속도·기어·주차 브레이크 읽기 퍼미션 | 표준 속성(`CAR_SPEED`·`CAR_POWERTRAIN`)과 Pleos Vehicle SDK로 읽는다. 주차 브레이크는 정차 판단에 쓰지 않고 참고로만 보여 준다. |
| EV 배터리 읽기 퍼미션(`CAR_ENERGY`) | 배터리 잔량·용량·주행 가능 거리를 SDK 우선으로 읽어 배터리 카드에 쓴다. |
| 위치 획득 방법 | NaviHelper가 알려 주는 차량 현재 위치를 쓴다(별도 위치 권한 없음). |
| NaviHelper 퍼미션 | `NAVI_ROUTE_SEARCH`·`NAVI_ROUTE`·`NAVI_NOTIFY`를 선언한다. |
| 에뮬레이터 제공 신청 | Pleos Connect Emulator로 개발 중이다. 운영사무국: 에뮬레이터 개발·시험에 승인 필요 없음(11-11). |
